# PiTun v2.0 — Руководство по новым функциям

## Обзор

PiTun v2.0 добавляет 7 новых модулей. Все работают автоматически после
установки — настройка нужна только для тонкой настройки.

---

## 1. Ad Blocking (DNS-уровень)

### Как работает
PiTun перехватывает все DNS-запросы LAN-устройств (через TPROXY на
порту 53/5353). При включённом AdBlocking, домены из чёрного списка
резолвятся в `0.0.0.0` — браузер сразу получает "нет ответа" и не
обращается к рекламному серверу. Трафик до прокси не доходит.

### Настройка

**Автоматически:** при первом запуске v2.0 seeded список StevenBlack
Unified Hosts (80k+ доменов). Чтобы его скачать:
```bash
# Найти ID списка
curl -s -H "Authorization: Bearer <token>" http://127.0.0.1:8000/api/adblock/lists | python3 -m json.tool

# Скачать (при активном прокси — через ноду)
curl -X POST -H "Authorization: Bearer <token>" http://127.0.0.1:8000/api/adblock/lists/1/refresh
```

**Добавить домен вручную:**
```bash
curl -X POST -H "Content-Type: application/json" -H "Authorization: Bearer <token>" \
  http://127.0.0.1:8000/api/adblock/rules \
  -d '{"domain_pattern": "ads.example.com", "rule_type": "block"}'
```

**Whitelist (разрешить домен):**
```bash
curl -X POST -H "Content-Type: application/json" -H "Authorization: Bearer <token>" \
  http://127.0.0.1:8000/api/adblock/rules \
  -d '{"domain_pattern": "example.com", "rule_type": "allow"}'
```

**Подписаться на новый список:**
```bash
curl -X POST -H "Content-Type: application/json" -H "Authorization: Bearer <token>" \
  http://127.0.0.1:8000/api/adblock/lists \
  -d '{"name": "EasyPrivacy", "url": "https://filters.adtidy.org/extension/chromium/filters/15.txt", "format": "domain"}'
```

**Статистика:**
```bash
curl -s -H "Authorization: Bearer <token>" http://127.0.0.1:8000/api/adblock/stats
```

### Интеграция с xray
AdBlock engine готовит `{domain: "0.0.0.0"}` карту для xray DNS hosts.
Config generator подставит её автоматически (TODO: интеграция в `config_gen.py`).

## 2. Prometheus Exporter

### Как работает
Backend отдаёт метрики в текстовом формате Prometheus на `GET /metrics`
(без авторизации — nftables уже ограничивает порт 8000 до LAN).

### Метрики

| Метрика | Тип | Описание |
|---------|-----|----------|
| `pitun_up` | gauge | Backend жив (1) |
| `pitun_cpu_percent` | gauge | CPU % |
| `pitun_ram_used_mb` | gauge | RAM используемая (MB) |
| `pitun_net_sent_bytes` | counter | Сетевой трафик (кумулятивный) |
| `pitun_node_latency_ms{node_id,node_name}` | gauge | Латентия ноды (ms) |
| `pitun_node_online{node_id,node_name}` | gauge | Нода онлайн (1/0) |
| `pitun_node_speed_mbps{node_id,node_name}` | gauge | Скорость (MB/s) |
| `pitun_outbound_uplink_bytes{tag}` | counter | Трафик per-outbound |
| `pitun_dns_queries_total` | counter | DNS-запросов за 24ч |
| `pitun_devices_total` | gauge | Всего устройств |
| `pitun_failover_events_total` | counter | Failover-событий за 24ч |
| `pitun_circle_rotations_total` | counter | Ротаций круга за 24ч |

### Настройка Grafana

```bash
# Запустить мониторинг-стек
cd /opt/pitun
COMPOSE_PROFILES=metrics docker compose up -d
```

- **Prometheus:** http://ваш-ip:9090
- **Grafana:** http://ваш-ip:3001 (admin/admin)

Datasource (Prometheus) уже auto-provisioned. Создай дашборд в Grafana
с запросами:
- `pitun_cpu_percent` — график CPU
- `pitun_node_latency_ms` — латенси по нодам
- `rate(pitun_outbound_uplink_bytes[5m])` — скорость трафика
- `pitun_node_online` — статус нод

## 3. SLA Uptime Dashboard

### Как работает
HealthChecker теперь пишет `NodeSLARecord` при каждой проверке (~30 сек).
Полуночный scheduler агрегирует данные в `NodeSLADaily` (uptime %,
avg/max/min latency, downtime events). Records старше 30 дней pruning.

### API

```bash
# Сводка по всем нодам (7d + 30d uptime)
curl -s -H "Authorization: Bearer <token>" http://127.0.0.1:8000/api/sla/summary

# История SLA одной ноды (30 дней)
curl -s -H "Authorization: Bearer <token>" http://127.0.0.1:8000/api/sla/nodes/3?days=30
```

### Что показывает
- **uptime_7d** / **uptime_30d** — % времени онлайн
- **avg_latency_7d** — средняя латенси за неделю
- **downtime_events** — сколько раз падала
- **total_downtime_seconds** — суммарное время простоя

### Автоматически
- SLA records пишутся при каждом healthcheck
- Агрегация запускается в полночь UTC
- Pruning — 30 дней для records, 1+ год для daily aggregates

## 4. Bandwidth per Device

### Как работает
Traffic collector опрашивает xray stats API каждые 30 секунд, вычисляет
дельту (сколько байт прошло за интервал) и сохраняет в `DeviceTraffic`.

### API

```bash
# Топ потребителей за 24ч
curl -s -H "Authorization: Bearer <token>" http://127.0.0.1:8000/api/traffic/summary?hours=24

# Time-series для конкретного устройства
curl -s -H "Authorization: Bearer <token>" http://127.0.0.1:8000/api/traffic/device/5?hours=24

# Агрегированный трафик (все устройства)
curl -s -H "Authorization: Bearer <token>" http://127.0.0.1:8000/api/traffic/aggregate?hours=24
```

### Ограничения
- Per-device пока работает как aggregate (нет per-MAC nftables counters)
- Данные хранятся 7 дней (5min intervals)
- Pruning automatically

## 5. Traffic Caps (Monthly Limits)

### Как работает
Quota checker каждые 60 сек агрегирует трафик в `TrafficUsage` (месячный
бакет). При превышении лимита emit event `traffic.quota_exceeded`.

### Настройка квоты

```bash
# Установить лимит 50GB/мес для устройства #3
curl -X POST -H "Content-Type: application/json" -H "Authorization: Bearer <token>" \
  http://127.0.0.1:8000/api/quotas \
  -d '{"scope_type": "device", "scope_id": 3, "monthly_limit_gb": 50, "action": "block"}'

# Глобальный лимит 500GB/мес с fallback на другую ноду
curl -X POST -H "Content-Type: application/json" -H "Authorization: Bearer <token>" \
  http://127.0.0.1:8000/api/quotas \
  -d '{"scope_type": "global", "monthly_limit_gb": 500, "action": "fallback", "fallback_node_id": 5}'
```

### Действия (action)
- **block** — заблокировать трафик (TODO: nftables drop)
- **fallback** — переключить на fallback ноду (TODO: config swap)
- **throttle** — ограничить скорость (TODO: nftables rate-limit)

### Текущий расход
```bash
curl -s -H "Authorization: Bearer <token>" http://127.0.0.1:8000/api/quotas/usage
```

### Автоматически
- Агрегация DeviceTraffic → TrafficUsage каждые 60 сек
- Проверка лимитов каждые 60 сек
- Event в ленте при превышении (dedup 1 час)
- Reset в 1-е число месяца (настраивается `reset_day`)

## 6. Rule Suggestions (DNS-log analysis)

### Как работает
Ежедневный scheduler анализирует `DNSQueryLog` за последние 7 дней.
Для доменов с > 10 запросов предлагает правило маршрутизации через
ноду с наименьшей латенси.

### API

```bash
# Список pending suggestions
curl -s -H "Authorization: Bearer <token>" http://127.0.0.1:8000/api/suggestions

# Принять suggestion (создаёт RoutingRule)
curl -X POST -H "Authorization: Bearer <token>" http://127.0.0.1:8000/api/suggestions/1/accept

# Отклонить
curl -X POST -H "Authorization: Bearer <token>" http://127.0.0.1:8000/api/suggestions/1/dismiss
```

### Что показывает
- **domain** — часто запрашиваемый домен
- **query_count** — сколько запросов за 7 дней
- **suggested_node_id** — нода с минимальной латенси
- **reason** — почему предложено (человекочитаемо)

### Автоматически
- Анализ запускается через 10 минут после boot, затем каждые 24 часа
- Suggestions expire через 7 дней если не приняты
- При accept создаётся RoutingRule (domain → node)

## 7. Connection Tracker (Live View)

### Как работает
Читает `/proc/net/nf_conntrack` (или `conntrack -L`), парсит активные
соединения и enriches: IP → Device (через ARP), dst IP → страна (GeoIP),
node через который идёт трафик.

### API

```bash
# Snapshot активных соединений
curl -s -H "Authorization: Bearer <token>" http://127.0.0.1:8000/api/connections/snapshot

# Сводка (протоколы, состояния)
curl -s -H "Authorization: Bearer <token>" http://127.0.0.1:8000/api/connections/summary
```

### Что показывает
- **device_name** — имя устройства (из Devices)
- **dst_ip** — destination IP
- **country** — ISO код страны (если GeoIP включён)
- **service** — имя сервиса (HTTP/HTTPS/SSH/etc.)
- **via_node** — через какую ноду идёт трафик
- **bytes** — байты по соединению (если доступно из conntrack)

### Требования
- `/proc/net/nf_conntrack` должен существовать (нужен `nf_conntrack` модуль)
- Для GeoIP: `GeoLite2-Country.mmdb` рядом с geoip/geosite данными
- Требует `conntrack` пакет если `/proc/net/nf_conntrack` недоступен
